# Anna Spiechowicz

Bilingual portfolio for Anna Spiechowicz, Product Owner and Business Analyst.

Static site built with Astro 7 and TypeScript. No client framework or CSS framework:
self-hosted IBM Plex Sans Variable and IBM Plex Mono, hand-written CSS, inline SVG
diagrams, and small browser scripts for navigation, theme switching and motion.

## Development

Use Node.js 26.x, as specified in `.nvmrc` and `package.json`.

```sh
npm install
npm run dev
```

The production build is static and is deployed by Vercel:

```sh
npm run build    # astro check + astro build -> dist/
npm run preview
```

English is served at `/` and German at `/de/`. The legal pages are in German.
`npm run check` runs Astro's diagnostics without building the site.

To restyle the site, start with the custom properties in `:root` and
`:root[data-theme="dark"]` at the top of `global.css`. Update both themes' accent
values, including `--accent-deep`; the diagrams share these tokens. Social images
and favicons are separate assets and need separate updates.

## Theme

Light and dark are both hand-tuned; the header carries a two-way switch.
**Light is the default and the site does not follow `prefers-color-scheme`** —
a visitor whose system is set to dark still gets the light page until they ask
for dark. That is deliberate: following the system preference meant most
visitors landed on the dark theme without ever choosing it.

Dark is therefore only ever an explicit choice. It is stored in `localStorage`
under `theme`, defined once in `global.css` under `:root[data-theme="dark"]`,
and applied by a small inline script in `<head>` before first paint so a chosen
dark theme never flashes light on load. With JavaScript disabled the page is
light.

## How the animations are made

The diagrams are inline SVG generated by Astro components, animated with CSS
keyframes in [global.css](src/styles/global.css). There is no animation library,
canvas, video or Lottie asset. JavaScript triggers the scroll reveals and animates
the metric numbers.

### Hero decision board

[DecisionBoard.astro](src/components/DecisionBoard.astro) defines the input boxes
and curved routes as coordinate data in a `460 × 360` SVG. Each route's path is
used both for the visible line and as the travelling dot's CSS `offset-path`.
The `travel` keyframes animate `offset-distance` from `0%` to `100%`, with an
opacity fade at either end.

Each route has two dots, offset by half of the 3.6-second cycle. Per-input delays
stagger the dots and LED strips; the `led` keyframes fill each strip using
`scaleX`. Separate keyframes pulse the centre ring, rotate the dashed orbit,
blink the status indicator and fill the output segments.

To change the geometry or stagger, edit `chips`, `routes` and `signals` in the
component. To change the motion, edit `travel`, `led`, `ping`, `spin`, `blink`
and `segfill` in the stylesheet. Keep the dot spacing and LED timing aligned
if you change the cycle length.

### Approach process diagram

[MethodProcess.astro](src/components/MethodProcess.astro) draws a BPMN-style
process with start/end events, four tasks, data objects and a decision gateway.
A moving token follows the forward path on a repeating 9-second cycle, pausing
at each task and the gateway while their outlines and fills highlight. The
return-to-Listen connector is drawn, but the token follows the forward path only.

The component generates horizontal and vertical SVG layouts; CSS switches to
the vertical version at `40rem` and below. Both place the stops at the same
fractions of the motion path, so they share the `bpmn-token` keyframes.
The component's `ACTIVE` table supplies highlight delays through `--delay`.
**Edit `ACTIVE` and the `bpmn-token` keyframes together** when changing the
sequence or timing. The wide layout also calculates the text-column spacing
from the diagram geometry to keep descriptions aligned with their tasks.

### Reveals, counters and vocabulary

[PortfolioPage.astro](src/components/PortfolioPage.astro) contains the browser
scripts and repeated vocabulary markup:

- **Scroll reveals:** an `IntersectionObserver` adds `.is-visible` to each target
  on first entry, then stops observing it. CSS fades and lifts reveal elements
  into place over 720ms and starts the diagram and vocabulary loops. Once
  started, those loops continue when scrolled offscreen; they are not scroll-scrubbed.
- **Metric counters:** a separate observer starts a 1.5-second JavaScript
  `requestAnimationFrame` count-up with cubic ease-out. Final numbers are already
  present in the HTML; animation is an enhancement.
- **Working vocabulary:** each row repeats its list three times. CSS translates
  the track by one third of its width for a seamless loop; the rows move in
  opposite directions over 44 and 52 seconds. Duplicate passes are hidden from
  assistive technology.
- **Reading progress:** the thin bar at the top uses CSS
  `animation-timeline: scroll()`, independently of the observers. It is enabled
  through `@supports` and stays hidden when that feature is unavailable.

The experience total is `years`, computed at build time from the current year
minus `careerStart` in `src/data/site.ts`. It needs a new build to reflect a new
calendar year; there is no `--years` CSS variable.

### Reduced motion and fallbacks

With `prefers-reduced-motion: reduce`, the diagram and vocabulary loops do not
start, count-ups are skipped, content is shown immediately, and the process token
and reading-progress bar are hidden. CSS also makes transitions effectively
instant and disables smooth scrolling.

Without JavaScript, content and final metric values remain visible and the
observer-triggered loops do not start. If `IntersectionObserver` is unavailable,
the script reveals all targets immediately and skips count-ups; CSS loops can
still run when reduced motion is not requested.

## Launch checklist

- Anna reviews and approves the English and German copy.
- Anna or a qualified adviser reviews the Impressum and privacy notice.

- The custom domain points to the approved production deployment.
